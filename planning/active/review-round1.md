## Findings

- **[fragile — test cannot fail]** `tests/testthat/test-fl_valley_join.R:254-265`. The "empty geometries skipped" half of this test cannot fail for the defect it names. I replaced `R/fl_valley_join.R:185` (`segments <- segments[!sf::st_is_empty(...), ]`) with `NULL` and the whole file stayed green. The fixture adds an empty `"A"` segment *beside* A's real segment, and `sf::st_nearest_feature()` already skips an empty candidate when a non-empty one exists. The drop matters only when every segment of a claiming group is empty. Then `st_nearest_feature(pts, <empty only>)` returns `NA` (measured), so without the drop the group would get `seg = NA` and an `NA` distance instead of being listed in `no_segments` with `dist = Inf`. Make the empty row the only segment of some claiming group (for example, a third group or a group-B-only fixture) so the mutation goes red.

- **[doc states something false, narrow]** `R/fl_valley_join.R:88`: "A cell is inside a row of `attributed` when its centre is". `terra::cells(x, <polygons>)` defaults to `small = TRUE`, which gives a polygon that covers no cell centre the cell(s) it overlaps. Measured: a 1 m x 1 m polygon for group B at (41-42, 41-42), which covers no centre, claimed the cell centred at (45, 45), and B's TRUE segment then made `any` TRUE there. An unmodified `fl_valley_attribute()` output is unaffected: its polygons are cell unions, and `small = FALSE` gives the same 65,495 claims on the tile. So the second half of the sentence holds. But for the simplified or reprojected inputs that the `check` paragraph discusses, the stated rule is wrong. Fix one of two ways: pass `small = FALSE` in the `terra::cells()` call at line 194, which makes the sentence true (identical on the tile and on cell-union inputs, so the driver logs are unaffected), or reword the sentence.

- **[fragile — DIFF B]** `floodplains-hj/scripts/floodplain_lcc/fp_habitat_join.R:46` (`fp_hj_summ`), fed by `habitat_join-query.R:88` and `habitat_join-demo.R:92`. The package deliberately returns `NA` flags for cells claimed only by a group with no segments; the old `fp_hj_join_range()` returned `FALSE`. `fp_hj_summ()` sums with no `na.rm`. So in any area where even one claiming blue line has no matched segment, every by-position hectare figure in the log becomes `NA` for that species, not just those cells' share. The same applies to the demo's `agree()` and `diff_builds()` sums. In the query script this can happen whenever `hs <- seg[!is.na(m), ]` drops all of a claiming blue line's segments (habitat_link not covering the schema). That case is reported (`habitat_rows_unmatched`, `segments_matched`) but not stopped. The committed logs are unaffected (0 such groups), so reproduction holds. A future area would print a table of NAs, and the only explanation would be the `blk_without_segments` column. The driver could either stop when `length(fr$no_segments) > 0` or sum with `na.rm = TRUE` and say so in the log.

- **[doc overstates a test, minor]** `CLAUDE.md:124`: "a reference copy of the floodplains implementation pins cell-for-cell equality and the 48 ties". Nothing asserts 48. The test asserts `out$ties > 0` and `out$ties == ref$ties` (`test-fl_valley_join.R:353,355`), so a change that moved both the function and the reference, for example a change in `fl_valley_attribute()` output, would pass with a different count. 48 is the current measured value, not a pinned one. Either reword ("the tie count, 48 on the tile") or add `expect_equal(out$ties, 48L)` if the literal is meant to be pinned.

No security issues. No data-loss paths.
